## 1. 整个控制器要解决的根本问题

打磨任务的本质困难：**你不知道工件表面在空间里精确的高度和朝向**，但打磨头必须持续压在表面上、保持一个目标力，同时沿着一条覆盖整个工件的轨迹移动。

如果全程用位置控制（告诉机械臂"移动到某个坐标"），你需要精确知道曲面每一点的高度，差一点点：
- 真实表面比你以为的高 → 机械臂继续下压穿过目标位置 → 接触力无限增大，可能损坏工件或打磨头。
- 真实表面比你以为的低 → 机械臂"到达目标位置"时其实还没碰到工件 → 接触力为 0，没有打磨。

这是**位置控制在未知/不确定环境接触任务里的根本缺陷**。解决办法是把问题拆成两个子问题，分别用不同的控制律处理：
1. **还没接触工件时**（下降阶段）：位置/阻抗控制，把机械臂平滑地送到工件附近。
2. **已经接触工件、需要维持恒定压力时**（打磨阶段）：不再依赖位置信息，改用**接触力的测量值**做反馈——这就是显式力控制，它完全不需要知道"应该压到哪个坐标"，只需要知道"现在测到的力是多少、跟目标差多少"。

这是整个架构的第一层分解：**时间上的两阶段**（`t < APPROACH_TIME` vs `t >= APPROACH_TIME`，对应 `main()` 里的 `if/else`）。

## 3. 阻抗控制：原理推导

### 2.1 基本思想

阻抗控制不直接命令关节角度，而是把末端想象成一个通过弹簧和阻尼器连接到目标位置的物体：

\[
F = K_p(x_d - x) - K_d\dot x
\]

- \(K_p(x_d-x)\)：位置误差越大，弹簧把它往目标拉的力越大。
- \(-K_d\dot x\)：速度越快，阻尼产生的反向阻力越大，防止像弹簧一样反复振荡。

这个公式算出来的是**末端任务空间**（笛卡尔坐标系）里"期望的力"，不是关节角度，所以还需要一步把它转换成关节力矩。

### 2.2 临界阻尼：为什么 \(K_d = 2\sqrt{K_p}\,\zeta\)

把 \(F=K_p e - K_d\dot e\) 代入一个质量为 \(m\) 的物体的运动方程 \(m\ddot e = -K_p e - K_d \dot e\)（这是标准二阶系统），特征方程是：

\[
m\ddot e + K_d \dot e + K_p e = 0 \quad\Rightarrow\quad \ddot e + 2\zeta\omega_n \dot e + \omega_n^2 e = 0
\]

对照系数，\(\omega_n = \sqrt{K_p/m}\)，\(2\zeta\omega_n = K_d/m\)，解出：

\[
K_d = 2\zeta\sqrt{K_p \cdot m}
\]

代码里把 \(m\) 归一化为 1（\(K_d = 2\sqrt{K_p}\,\zeta\)），\(\zeta=1\) 时是**临界阻尼**——最快收敛到目标且不振荡；\(\zeta<1\) 会振荡但更快；\(\zeta>1\) 不振荡但迟钝。这不是拍脑袋定的系数，是解二阶微分方程解出来的。

### 2.3 从任务空间力到关节力矩：雅可比转置

阻抗控制算出来的 \(F\) 是笛卡尔空间的力，机械臂只能直接控制关节力矩 \(\tau\)。转换用的是**虚功原理**：末端力做的虚功必须等于关节力矩做的虚功。

\[
\delta W = F^\top \delta x = F^\top (J\,\delta q) = (J^\top F)^\top \delta q = \tau^\top \delta q
\]

所以 \(\tau = J^\top F\)。这里 \(J\) 是雅可比矩阵，把关节速度映射到末端速度（\(\dot x = J\dot q\)）；反过来，它的转置把末端力映射回关节力矩——方向相反，但数学上严格配对，不是巧合，是虚功原理的直接推论。

**代码实现**：`mj_jacSite` 算出 `jacp`（位置雅可比）`jacr`（姿态雅可比），拼成 6×7（或 RM65-B 上是 6×6）的 `J`；`tau_task = J.T @ F_task`；再加上 `qfrc_bias`（MuJoCo 算好的重力+科氏力项）做前馈补偿，这样阻抗律只需要处理"任务误差"，不用再分心对抗重力。

## 4. 显式力控制：原理推导

### 3.1 力控制律

\[
F_n^{\text{cmd}} = -\Big(f_{\text{target}} + K_{p,f}\,e + K_{i,f}\!\!\int e\,dt\Big) - B_z\,(\dot{\vec x}\cdot\hat n), \qquad e = f_{\text{target}} - f_{\text{filt}}
\]

这是一个 **PI（比例积分）控制器 + 纯阻尼项**：
- \(f_{\text{target}}\)：前馈项，直接告诉执行机构"稳态应该输出多大力"。
- \(K_{p,f}\,e\)：比例项，误差越大修正越大，负责快速响应。
- \(K_{i,f}\!\int e\,dt\)：积分项，专门消除**稳态残余误差**（摩擦、模型误差导致比例项单独消不掉的偏差）。
- \(-B_z\dot x_n\)：纯阻尼，没有对应的"目标"，只是抑制法线方向速度，防止高频弹跳——这是为了接触稳定性，跟"往哪个目标去"无关。

### 3.2 抗积分饱和

如果长时间跟不上目标力，积分项会无限累加，一旦突然跟上会因为过大的积累值产生剧烈超调。用 `np.clip(f_integral, -I_CLAMP, I_CLAMP)` 把积分限制在一个范围内——这是 PI/PID 控制器的标准工程技巧，叫 anti-windup。

### 3.3 ★最关键的一条原理：同一个自由度上不能同时用位置刚度和力积分

假设在同一根轴上，除了力控制公式，还保留了一份位置刚度项 \(K_{p,\text{pos}}(x_{\text{guess}}-x)\)。位置项说"往我猜的那个高度去"，力积分项说"往能维持目标力的高度去"——两者通常不是同一个高度，且都在往同一个物理量（法向压深）上使劲，方向经常相反，会互相打架、叠加出振荡。**这不是参数没调好，是同一根自由度被两套closed-loop同时抢主导权**，本质上是控制系统里"没有让两个反馈环正交"的错误。

**代码实现**：`f_err = F_TARGET - f_filt; f_integral = clip(...); Fn_cmd = -(F_TARGET + KP_F*f_err + KI_F*f_integral) - BZ*vn`，法线方向打磨阶段只有这一套力指令+阻尼，没有额外的位置刚度混进来。

## 5. 世界系分解 vs 表面系分解：完整推导

### 4.1 为什么 world -z 不对：\(1/\cos\theta\) 过压推导

假设接触力矢量确实沿着真实表面法线 \(\hat n\)（低摩擦假设，静止或缓慢接触时合理），大小为 \(f_n\)：

\[
\vec f_{\text{raw}} = f_n\,\hat n
\]

如果只读世界 z 分量（旧写法 `f_raw[2]`），实际读到的是这个矢量在世界 \(\hat z\) 方向上的投影：

\[
f_{z,\text{raw}} = \vec f_{\text{raw}}\cdot\hat z = f_n(\hat n\cdot\hat z) = f_n\cos\theta
\]

其中 \(\theta\) 是局部法线相对世界竖直方向的倾角。控制器把 \(f_{z,\text{raw}}\) 调节到目标值 \(F_{\text{target}}\)，也就是让 \(f_n\cos\theta = F_{\text{target}}\)，反解出真实法向力：

\[
f_n = \frac{F_{\text{target}}}{\cos\theta} > F_{\text{target}}
\]

因为 \(\cos\theta<1\)，真实压力永远比目标值大——圆弧倾角越大的地方压得越狠。**这是纯几何投影必然带来的系统性偏差，跟增益调得好不好完全无关**。

### 4.2 修复：把控制方向从"世界 z"换成"局部法线"

```python
f_n_raw = f_raw @ local_normal          # 点积：把力矢量投影到真实法线上
Fn_cmd = -(f_target + Kp_f*f_err + Ki_f*integral) - Bz*(x_dot @ local_normal)
F_normal = Fn_cmd * local_normal        # 标量力撑开成沿法线方向的力矢量
```

调节的直接就是 \(f_n\) 本身，不存在 \(1/\cos\theta\) 偏差。**实测验证**：圆弧区真实法向力误差从 0.616N 降到 0.239N（约 2.6 倍），平均压力从 8.58N（过压 7.3%）降到 8.01N。

### 4.3 切平面投影：为什么两个子空间的力可以直接相加

任何 3 维向量都可以唯一分解成"沿 \(\hat n\)"和"垂直于 \(\hat n\)"两部分之和：

\[
\vec v = (\vec v\cdot\hat n)\hat n + \big[\vec v - (\vec v\cdot\hat n)\hat n\big]
\]

第二项跟 \(\hat n\) 严格正交。代码里 `pos_err_tan = pos_err - (pos_err @ n) * n` 就是减去沿法线方向的分量，剩下的必然落在切平面内。因为 `F_normal` 严格躺在 \(\hat n\) 方向、`F_tangent` 严格躺在切平面内，**`F_xyz = F_normal + F_tangent` 直接相加就等价于在完整 3 维空间里同时满足两个约束，不会互相抵消或产生意料之外的耦合**——这是线性代数正交分解的直接推论，不是工程经验，是可以证明的性质。

在平面区域 \(\hat n=(0,0,1)\)，这套分解精确退化成旧的"z 分量/xy 分量"写法（代数恒等），这也是验证"新功能没有破坏旧行为"的方式。

## 6. 感知原理：深度相机 → 点云 → 局部法线

### 5.1 针孔相机反投影

深度相机每个像素给出"沿相机视线方向到物体的距离" \(d\)。标准针孔相机模型把像素坐标 \((u,v)\) 和深度 \(d\) 转换成相机坐标系下的 3D 点：

\[
x_{\text{cam}} = \frac{u-c_x}{f}d,\qquad y_{\text{cam}} = -\frac{v-c_y}{f}d,\qquad z_{\text{cam}} = -d
\]

再用相机的世界位姿（旋转矩阵+平移）把点转换到世界坐标系。这一步跟"作弊读公式"完全无关，纯粹是几何重建。

### 5.2 SVD 拟合局部平面：为什么最小奇异向量是法线

把某个局部窗口内的点云中心化（减去质心）后做 SVD 分解。SVD 的几何意义：**分解出这批点在各个方向上的散布程度**，方向由奇异向量给出，散布大小由奇异值给出。如果这些点近似落在一个平面上，那么"点集分布最扁的方向"（散布最小、奇异值最小的方向）正是这个平面的法线方向——这是主成分分析（PCA）的标准结论，法线估计本质上是"找散布最小的方向"这个更一般问题的特例。

### 5.3 ★噪声临界点的完整推导——这是最容易被深挖的一个原理点

每个拟合窗口宽 \(2\times\text{SCAN\_BIN\_HALF\_WIDTH}=24\text{mm}\)。假设窗口内的点在 x 方向近似均匀分布，均匀分布 \(U(-a,a)\) 的标准差是：

\[
\sigma_x = \frac{2a}{\sqrt{12}} = \frac{24\text{mm}}{\sqrt{12}} \approx 6.9\text{mm}
\]

如果深度噪声的标准差也接近这个数量级，那么"z 方向的散布"（本该很小，因为窗口内表面近似平坦）和"x 方向的散布"（本来就有 6.9mm，是窗口宽度决定的）变得**同量级**——SVD 分不清哪个方向才是真正"最扁"的方向，最小奇异向量会在两个方向之间随机跳变。实测：噪声到 7mm 时法线误差从几度突然恶化到 50°-90°，不是缓慢退化，是几何意义上的**方向判断歧义**导致的断崖式失效。

修复靠**多帧平均**：对同一静态场景独立采集 \(N\) 帧噪声，平均后标准差按 \(\sigma_{\text{avg}}=\sigma/\sqrt N\) 下降（独立随机变量求和的方差可加性）。这是真实深度相机内部也在做的时序降噪，不是我们发明的技巧。**试过跨窗口中位数滤波，无效**——因为临界点附近是几乎所有窗口同时判断错误，不是少数窗口坏、多数窗口好，中位数滤波对"系统性错误占多数"这种情况无能为力。

### 5.4 感知必要性的证明——不是"看起来更真实"，是有数据支撑

做了三组对照（world 世界系 / analytic 解析作弊法线 / camera 真实点云法线），发现 analytic 和 camera 在圆弧区误差只差 0.7%。**这证明表面系分解带来的提升（2.6倍）来自"有没有一个准确的局部法线"这件事本身，跟法线是怎么来的无关；相机的价值是在不知道工件真实公式的前提下，把法线做到接近解析真值的精度**。

进一步测试："能不能不用相机，靠接触力方向反推法线"（低摩擦假设下 \(\vec f_{\text{raw}}\approx f_n\hat n\)，反过来归一化力矢量当法线用）。结果系统性地失败：法线角度误差 30.5°，力误差从 0.2N 恶化到 1.85-1.95N，**连平面区域都变差**。原因：打磨头一边压着 8N，一边主动沿光栅路径滑动，滑动摩擦力 \(\mu F_n\approx0.8\times8=6.4\)N，跟法向力几乎同量级，摩擦力方向跟着"往哪滑"走、不跟着"表面朝哪倾斜"走，把力矢量方向拽偏了近 30°。这个假设（低摩擦）只在打磨头静止时成立，一旦真的开始"压着蹭"（打磨任务的核心动作），假设就失效了。

## 7. 安全机制：控制理论层面的设计依据

### 6.1 为什么力上限不能直接设成目标值——这是 PI 控制器的固有需求

回到 §3.1 的公式：当 \(f_{\text{err}}>0\)（欠压），\(K_{p,f}\,e\) 天然是正的，这意味着命令值**理应短暂超过目标值**才能产生额外的拉力去纠正欠压——这是反馈控制"追目标"的必需机制，不是失误。如果把上限 \(F_{\max}\) 死死设成等于 \(F_{\text{target}}\)（零余量），等于把这个修正能力砍掉：欠压时命令值最多也只能等于目标值，没有额外推力去加速追赶，纠正变慢，抖动反而变大。实测验证：零余量下 std 从 0.318N 恶化到 0.347N，极差从 2.61N 恶化到 3.48N。留 1N 余量，让 PI 的修正机制正常工作，同时又给命令值设了一个不会失控的上限。

**结论**：真正负责"把力稳定在目标附近"的是 PI + 低通滤波这套闭环本身；力上限只是一个不参与常规调节、只在异常时介入的软约束，二者职责完全不同，不能互相替代。

### 6.2 双通道快慢滤波：频域上的设计原理

低通滤波器把信号分成"低频真实变化"和"高频求解器噪声"两部分，滤波器的截止频率 \(f_c\approx \alpha f_s/(2\pi)\)。

- **慢滤波**（\(\alpha=0.03\)，\(f_c\approx2.4\)Hz）：截止频率设得低，滤掉高频求解器噪声，专门服务于力控制的稳态精度——这个信号有意"迟钝"，因为它要过滤的噪声频率很高，而真实力变化很慢，迟钝换来的抗噪能力划算。
- **快滤波**（\(\alpha=0.2\)，反应速度约是慢滤波的 6 倍）：专门用来做安全监控，不参与力控制反馈——如果混进控制环，会把"服务于抗噪"的慢滤波设计意义直接抵消，重新引入第十章调参案例里验证过的抖动问题。安全监控需要的是"快"（真出问题要立刻抓到），跟力控制需要的"稳"（抗噪）是两个互相冲突的目标，用两个独立信号分别满足，而不是让一个信号同时兼顾。

### 6.3 感知独立的合力通道——为什么需要两条正交的安全判据

法向通道 \(f_{\text{raw}}\cdot\hat n\) 依赖法线估计——如果法线本身错了（比如指向了错误方向），这个投影可能因为投影到错误坐标轴而显得很小，掩盖真实的危险接触。合力通道 \(\lVert\vec f_{\text{raw}}\rVert\) 是矢量模长，**数学上不依赖任何坐标轴选择**——不管法线估计对不对，真实压力有多大就是多大。两个通道分别设不同阈值（法向 10N、合力 20N，合力更高是因为正常打磨时切向摩擦本来就会让矢量模长比单纯法向分量大），互为兜底，这是"用一个不依赖可能出错的中间变量的独立判据来防止单点故障"的标准安全设计思路。

### 6.4 撤离并锁定：为什么不能自动恢复

触发安全条件后，如果撤离-力下降-自动恢复-再次判断过力，一旦故障源头是**持续性的**（不是瞬时干扰），会陷入"退开→冲回去→又被拦下"的死循环，本质上是控制器在错误地假设"故障会自愈"。工业系统的标准做法是瞬时保护自动复位、但持续性故障必须锁定、等待人工确认——因为系统没有能力区分"这次是巧合还是会一直发生"，保守的默认行为应该是假设故障没有自愈，需要人工验证。

## 8. 已知的算法局限（主动讲，不要等被问出来）

- 法线拟合是逐窗口独立 SVD，没有利用相邻窗口的信息做联合平滑，是这次噪声测试暴露出的结构性盲区，不是参数问题。
- 安全机制目前只覆盖"力"相关风险，机械臂自身连杆的结构碰撞检测目前只打印日志、没有接入跳闸逻辑——15mm 噪声测试时实际发生过 4 次未被捕捉的碰撞。
- 只用视觉一种感知模态，没有拿力传感器数据做交叉验证；姿态/力控制/轨迹跟踪虽然统一读取同一个法线估计，但这个估计本身没有第二个独立信息源去验证对不对。
- PI 力控制的增益是针对当前任务/材质手调的固定常数，没有验证过大范围接触刚度下的稳定性边界（力控制理论里，接触刚度、采样频率、增益三者之间存在经典的稳定性约束）。
- 光栅路径是纯时间函数（`raster_xy(t)`），不读取任何实时状态，调度层面是开环的——某一行打磨质量不好，不会自动放慢或重做。
- 从未测试过闭环对**反馈延迟**的容忍度：仿真是零延迟同步的，这个稳定裕度目前完全未知，是唯一一个"已经想清楚怎么测、但还没测"的开放问题。
